首先在 xv6 项目根目录执行编译，生成可读的汇编输出文件。执行make fs.img，编译user/call.c，编译器会输出user/call.asm，这个文件就是 RISC V 汇编文本，不需要手动写汇编，只做阅读分析。
打开user/call.asm，依次定位g、f、main三个函数对应的汇编片段。先观察函数g的汇编，理解栈帧操作指令addi sp,sp,-16分配栈空间，sd保存被调用者保存寄存器s0，ld恢复寄存器，ret函数返回；观察参数传递寄存器a0，函数返回值同样存放在a0寄存器，注意编译器做了函数内联优化，f函数没有真正执行jal调用g，直接把g的运算逻辑展开。接着阅读main函数汇编，观察jalr进行函数调用，看printf传参，a0存放字符串指针，a1、a2存放后续参数，理解 RISC V 调用约定，参数使用a0 a7寄存器传递。

Q1：Which registers contain arguments to functions? For example, which register holds 13 in main's call to printf?
 
由图可以推断出a0‑a7这组寄存器用来存放函数参数。看出13存放在a2寄存器。
Q2：Where is the call to function f in the assembly code for main? Where is the call to g? (Hint: the compiler may inline functions.)
查看 call.asm 文件里的 f 函数与 g 函数可以看到，代码逻辑上 f 会调用 g，g 会将传入的参数自增 3 之后作为返回值返回。 
编译器会执行函数内联优化，对于编译阶段就能够确定的运算，会直接在编译期算出最终结果，不再生成实际的函数调用指令。在 main 函数中，printf 的参数包含 f (8)+1，但是对应的汇编代码并没有执行 f、g 的函数调用，而是直接写入了常量 12。 
由此能够看出，编译器对该处的函数调用做了编译期优化。因此在 main 的汇编实现中，不会出现对 f 和 g 的调用指令，f (8)+1 的计算在程序运行之前就已经由编译器完成。

Q4：What value is in the register ra just after the jalr to printf in main?
 
jalr rd, offset(rs) 的行为是把下一条指令的地址保存到 rd（这里是 ra），跳转到目标地址执行函数。
jalr 这条指令本身地址是 0x34，它的下一条指令就是 exit(0) 对应的指令，地址为 0x38。
所以执行完跳转到 printf 的 jalr 之后，寄存器 ra 里面存放的值是：0x38（十进制 56），这个就是函数返回地址，printf 执行完就会跳回 0x38 继续运行。
Q5：Run the following code.
	unsigned int i = 0x00646c72;
	printf("H%x Wo%s", 57616, &i);
      
What is the output? Here's an ASCII table that maps bytes to characters.
The output depends on that fact that the RISC-V is little-endian. If the RISC-V were instead big-endian what would you set i to in order to yield the same output? Would you need to change 57616 to a different value?
Here's a description of little- and big-endian and a more whimsical description.
在小端模式的 RISC V 机器上，unsigned int i = 0x00646c72在内存中由低地址到高地址存储的字节依次是0x72('r')、0x6c('l')、0x64('d')、0x00('\0')，&i传给%s会读出字符串rld，十进制 57616 转为十六进制为0xe110，按照printf("H%x Wo%s", 57616, &i)格式化，程序输出是He110 World；如果 RISC V 是大端序，要得到完全一样的输出，变量i应当赋值为0x726c6400，以此保证内存从低到高仍然是r、l、d、\0的字节序列；不需要修改 57616 这个数值，因为%x输出的是寄存器内部的整数，大小端只影响数据在内存中的字节存放顺序，不会改变寄存器里保存的整数本身的值。
Q6：In the following code, what is going to be printed after 'y='? (note: the answer is not a specific value.) Why does this happen?
	printf("x=%d y=%d", 3);
执行printf("x=%d y=%d", 3);后，y=后面会打印栈上随机的垃圾值（未初始化的内存值）。因为 printf的格式字符串里有两个%d格式占位符，但是程序只传入了 1 个实参3。C 语言可变参数函数不会检查参数数量，第一个%d取传入的参数 3 打印；第二个%d会继续从函数调用的参数栈（RISC V 中为参数寄存器）读取本不属于本次函数调用的、遗留的随机内存 / 寄存器数据，这属于未定义行为，因此 y 输出的不是确定数值。
